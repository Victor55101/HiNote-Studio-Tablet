# V39 estable — alternar teclado físico y virtual

V38 ocultaba el teclado virtual mientras hubiese un teclado conectado. V39
decide según la interacción más reciente y conserva el resto de V38.

- Tocar con el dedo o el lápiz un campo editable permite el teclado virtual,
  incluso con el teclado NearLink conectado. Se conservan los tipos de entrada
  de cada campo, incluidos los decimales de las gráficas.
- Escribir con teclas físicas, mover el puntero o usar el panel táctil oculta
  el teclado virtual. Los eventos siguen llegando al editor: no se consume
  la primera letra ni se mueve el cursor para realizar el cambio.
- Los botones, el arrastre y los gestos con dos dedos no solicitan abrir el
  teclado virtual. Una petición pendiente se cancela si se empieza a usar
  el teclado físico, el ratón, otra interacción o se sale de HiNote.
- Página → Teclado conserva Automático, Mostrar virtual y Solo físico. Los
  dos modos manuales respetan la elección del usuario.
- No cambia NearLink ni los ajustes globales del teclado. No requiere
  accesibilidad y no guarda el contenido de las teclas.

## Comprobación en la tablet

1. Instala V39 sobre V38 y deja NearLink activado. En Página → Teclado usa
   Automático.
2. Toca el texto del Documento: debe permitir el teclado virtual. Escribe
   después con el teclado físico: el virtual debe ocultarse y la primera
   letra debe aparecer en el cursor.
3. Vuelve a tocar el texto para mostrar el virtual; mueve el panel táctil
   para ocultarlo. Repite sin desvincular el teclado. Prueba también un campo
   de fórmula o gráfica.

Paquete `com.hinote.studio`, código 39, versión `3.9-tablet`. Se mantiene la
firma estable y el formato del borrador V38; no hay nueva migración de datos.

Las regresiones del editor comprueban toques reales, clics del ratón, posición
del cursor, campos decimales, arrastre, dos dedos y el modo Solo físico. Las
pruebas Android comprueban la alternancia con hardware conectado, la
clasificación de eventos y el rechazo de peticiones táctiles antiguas.
La combinación concreta de NearLink, WebView y SwiftKey se comprueba en la
tablet: las pruebas automatizadas no reproducen ese hardware.

Referencias de implementación: [fuentes de entrada](https://developer.android.com/reference/android/view/InputDevice),
[solicitud explícita del teclado](https://developer.android.com/reference/android/view/inputmethod/InputMethodManager#showSoftInput(android.view.View,%20int)).

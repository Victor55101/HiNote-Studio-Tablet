# V40 estable — teclado virtual cerrado durante la escritura física

En V39, el usuario observó que el teclado virtual aparecía y se ocultaba con
cada tecla física. La política anterior enviaba solicitudes de ocultación
repetidas, pero no impedía nuevas solicitudes de apertura de WebView/IME.

V40 mantiene la ventana de HiNote fuera de los destinos del teclado virtual
mientras se usan teclas físicas, ratón o panel táctil. Se aplica
`FLAG_ALT_FOCUSABLE_IM` sin quitar el foco de la ventana ni del editor. No se
consumen ni se duplican las teclas. Se oculta una vez al entrar en ese estado;
las teclas siguientes no reinician el teclado ni cambian la ventana.

Tocar con el dedo o lápiz un campo editable libera el bloqueo y permite
reconectar el teclado virtual. NearLink puede seguir conectado. Los modos
Automático, Mostrar virtual y Solo físico siguen disponibles en Página.
No se modifican ajustes globales ni permisos. Se conserva el formato del
borrador V38 y el resto de las funciones de V39.

## Comprobación en la tablet

1. Instala V40 sobre V39, mantén NearLink conectado y elige Página → Teclado →
   Automático.
2. Toca el Documento con el dedo para usar el virtual. Escribe luego varias
   frases con el teclado físico, incluyendo tildes, ñ, espacios, Enter y
   retroceso. El virtual debe cerrarse una vez y permanecer cerrado. Comprueba
   que no falte la primera letra y que el cursor se conserve.
3. Toca el texto con el dedo para volver al virtual. Alterna varias veces;
   prueba también el panel táctil, el título y un campo de fórmula o gráfica.
4. Sal de HiNote y vuelve: verifica que otros programas conservan su teclado
   habitual y que puedes seguir alternando al regresar.

Código 40, versión `4.0-tablet`, paquete `com.hinote.studio`, firma estable.

Las pruebas Android comprueban que la ventana no admite el teclado virtual
durante una secuencia de 60 teclas, mantiene el foco, conserva otros atributos
y restaura la entrada virtual con el dedo. También cubren modos manuales,
ratón, pausa/reanudación y desconexión en API 28 y 31. Las pruebas del editor
cubren escritura y posición del cursor, toques, arrastres y campos decimales.
La ausencia de parpadeo con NearLink y SwiftKey requiere la comprobación en
la tablet; Robolectric y el navegador no ejecutan esa combinación real.

Referencia: [política pública de foco del método de entrada de Android](https://developer.android.com/reference/android/view/WindowManager.LayoutParams#FLAG_ALT_FOCUSABLE_IM).
